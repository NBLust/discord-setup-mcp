# Discord Server Setup MCP

An MCP (Model Context Protocol) server that lets an AI assistant like Claude **build out and fill a Discord server** through a bot — structure (channels, categories, roles, permissions, settings), **real content** (messages, embeds, pinned guides, forum posts), modern **server features** (AutoMod, scheduled events, onboarding, welcome screen), and full **custom blueprints** applied idempotently.

> **v3.0.0** — REST-only rewrite (no gateway, no privileged intents), a custom blueprint engine, a content layer, and 16 new tools. See [Version History](#version-history).

## What it can (and cannot) do

A Discord **bot cannot create a blank server** — the API rejects it (`POST /guilds` → `20001 "Bots cannot use this endpoint"`). So the workflow is:

1. **You** create an empty server in Discord (`+` → *Create My Own*) — 10 seconds.
2. **You** invite the bot with the [invite URL](#2-invite-the-bot) (Administrator).
3. **Claude** builds and fills everything via this MCP.

Everything else — every channel, role, permission, message, AutoMod rule, event, and the whole Community feature stack — the bot does for you.

## Features

- **Custom blueprints** — describe a whole server (inline object generated by Claude, or a versioned YAML/JSON file) and apply it **idempotently** (re-apply never duplicates), with a **dry-run plan** first. Plus `export_server` to clone an existing server into a blueprint.
- **Content layer** — `send_message`, `post_embed`, `pin_message`, `create_forum_post`, `post_via_webhook` (personas), and link-button messages, so a built server isn't empty.
- **Structure** — create/edit/delete channels (text, voice, announcement, stage, forum, media), categories, and roles with full permission overwrites.
- **Server features** — AutoMod rules, scheduled events, invites, `enable_community`, onboarding, welcome screen, server icon.
- **Pre-built templates** — gaming, community, business, study-group.
- **REST-only** — no gateway connection, **no privileged intents**, instant cold start, bucket-aware rate limiting.

## Prerequisites

- **Node.js** 18 or higher
- A **Discord bot** — created once in the Developer Portal (steps below). No privileged intents required.

### Step 1 — Create the application and bot

1. Go to the [Discord Developer Portal](https://discord.com/developers/applications) and click **New Application**. Name it (this becomes the bot's name) and create it.
2. Open the **Bot** tab in the left sidebar (the bot user already exists for new apps; if prompted, click **Add Bot**).
3. Under **Bot → Token**, click **Reset Token**, confirm, and **copy the token**. This is the secret you configure in [Configuration](#configuration) — treat it like a password and never commit it.
4. **Privileged Gateway Intents — none required.** This server is REST-only and never opens a gateway connection, so leave Presence, Server Members, and Message Content **off**.
5. From the **General Information** tab, copy the **Application ID** (you need it for the invite URL).

### Step 2 — Invite the bot to your server

A bot **cannot create a server** (see [What it can and cannot do](#what-it-can-and-cannot-do)), so it has to be invited to one that already exists:

1. In Discord, create an empty server: the **+** button in the server sidebar → **Create My Own** → name it.
2. Build this invite URL, replacing `YOUR_APP_ID` with your Application ID:
   ```
   https://discord.com/oauth2/authorize?client_id=YOUR_APP_ID&scope=bot+applications.commands&permissions=8
   ```
3. Open it in a browser, pick your server in the **Add to Server** dropdown, and click **Authorize**.

`permissions=8` is **Administrator** — recommended, because the bot manages roles, channels, permissions, webhooks, AutoMod, and the Community feature stack on your behalf. Even with Administrator, Discord's hierarchy rule still applies: the bot can only manage roles **below** its own highest role, so keep the bot's role near the top of **Server Settings → Roles**.

Once the bot is in your server, ask Claude something like *"list my Discord servers"* and start building.


## Configuration

Provide the token via environment variable **or** a config file.

**Environment variable:**
```bash
export DISCORD_BOT_TOKEN="your-bot-token"
```

**Config file** `~/.discord-mcp/config.json` (recommended; keep it out of version control):
```bash
mkdir -p ~/.discord-mcp
cat > ~/.discord-mcp/config.json << 'EOF'
{ "discordToken": "your-bot-token", "defaultGuildId": "optional-default-server-id" }
EOF
chmod 600 ~/.discord-mcp/config.json
```

### Claude Code

```bash
claude mcp add -s user discord-setup node /absolute/path/to/discord-setup-mcp/dist/index.js
```
(The token is read from the env var or `~/.discord-mcp/config.json`; no need to pass it on the command line.)

### Claude Desktop

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) / `%APPDATA%\Claude\claude_desktop_config.json` (Windows):
```json
{
  "mcpServers": {
    "discord-setup": {
      "command": "node",
      "args": ["/absolute/path/to/discord-setup-mcp/dist/index.js"],
      "env": { "DISCORD_BOT_TOKEN": "your-bot-token" }
    }
  }
}
```

## Blueprints (the core)

Describe a server and apply it idempotently. Inline (Claude generates it from your description) or a versioned file.

```yaml
# blueprints/example.yaml
guild:
  verificationLevel: low
roles:
  - name: Team
    color: "#5865F2"
    permissions: [MANAGE_MESSAGES, KICK_MEMBERS]
categories:
  - name: INFO
    channels:
      - name: announcements
        type: text
        messages:
          - content: "Welcome! Read the rules below."
            pin: true
      - name: rules
        type: text
```

- `plan_blueprint` — dry-run: what would be created/updated/skipped, plus warnings (Community-gated channels, Discord limits). No mutation.
- `apply_blueprint` — applies idempotently (diff by name → create/update/skip). Per-channel `messages[]` are seeded **only when a channel is first created**, so re-applying never duplicates content.
- `export_server` — read a live server → a blueprint object you can save and re-apply elsewhere.

Overwrites reference role **names** (or `@everyone`).

## Tool Reference

**Guild:** `list_guilds`, `select_guild`, `get_guild_info`
**Channels:** `create_category`, `create_channel`, `edit_channel`, `delete_channel`
**Roles:** `create_role`, `edit_role`, `delete_role`, `reorder_roles`
**Settings:** `update_server_settings`, `set_verification_level`, `set_content_filter`, `set_default_notifications`
**Content:** `send_message`, `post_embed`, `pin_message`, `create_forum_post`, `post_via_webhook`, `post_message_with_components`
**Blueprints:** `apply_blueprint`, `plan_blueprint`, `export_server`
**Server features:** `configure_automod`, `create_scheduled_event`, `create_invite`, `enable_community`, `configure_onboarding`, `set_welcome_screen`, `set_server_branding`
**Templates:** `list_templates`, `preview_template`, `apply_template`

Permission names use `SCREAMING_SNAKE_CASE` (e.g. `VIEW_CHANNEL`, `MANAGE_MESSAGES`, `PIN_MESSAGES`). Common UI-style synonyms are accepted too (`MANAGE_SERVER`, `TIMEOUT_MEMBERS`, `VIDEO`, …); anything unrecognized is rejected with an error rather than silently dropped. Permission overwrites: `{ id, type: "role"|"member", allow: [...], deny: [...] }`.

## Limits (what a bot genuinely cannot do)

- **Create a blank server** — blocked by Discord (`20001`). Invite the bot to a server you created.
- **Vanity URL** and **Server Tags** — no bot-accessible write API.
- **Banner / splash** — boost-gated; only the **icon** is guaranteed.
- **Interactive components** (button/select clicks) — require an always-on gateway listener; this server is request/response, so only **link buttons** are supported.
- **Community-gated features** (announcement/stage channels, onboarding, welcome screen) — require Community; run `enable_community` first (needs Administrator).
- **Role hierarchy** — the bot only manages roles below its own and grants only permissions it holds.

## Security

- Treat the bot token like a password; never commit it. Regenerate it in the Developer Portal if exposed.
- `chmod 600 ~/.discord-mcp/config.json`.
- Only add the bot to servers you trust.

## Architecture

- **Runtime:** Node.js 18+ — REST-only, no gateway connection, no intents.
- **HTTP:** `@discordjs/rest` (bucket-aware rate limiting) via discord.js 14.26; route builders from `discord-api-types`. discord.js is used for builders/constants only.
- **MCP SDK:** `@modelcontextprotocol/sdk` 1.29 (`registerTool`).
- **Validation:** zod. **Blueprints:** yaml.
- **Tests:** vitest (unit) + live smoke checks against a dedicated test server.

> Note: `npm audit` reports a few transitive advisories from the MCP SDK's optional Hono HTTP transport. This server is **stdio-only** and never loads that transport, so they are not reachable.

See [CLAUDE.md](CLAUDE.md) for development docs.

## Version History

- **3.1.0** — Strict permission-name mapping: unknown names now raise a clear error instead of being silently dropped (a typo'd `deny` could previously leave a channel exposed), with legacy/UI synonyms (`MANAGE_SERVER`, `TIMEOUT_MEMBERS`, `VIDEO`, …) accepted; permission list for `create_role`/`edit_role` derived from discord.js (picks up `SEND_POLLS`, `USE_EXTERNAL_APPS`, `SET_VOICE_CHANNEL_STATUS`); blueprint embeds validated at load time; `plan_blueprint`/`apply_blueprint` warn about overwrites referencing unknown roles; blueprints seed messages in announcement channels and diff/patch voice `bitrate`/`userLimit`; invalid colors rejected instead of sent as `NaN`; `rateLimit.maxRetries` config now actually wired into the REST client; removed dead v2 validation module.
- **3.0.0** — REST-only rewrite (removed gateway/privileged intents); custom **blueprint engine** (inline + YAML/JSON, idempotent apply, dry-run plan, export); **content layer** (messages, embeds, pins, forum posts, webhooks, link buttons); **server features** (AutoMod, scheduled events, invites, Community/onboarding/welcome screen, branding); fixed the Nov-2025 permission split (`PIN_MESSAGES`, `BYPASS_SLOWMODE`, `CREATE_GUILD_EXPRESSIONS`, `CREATE_EVENTS`); fixed raw-`fetch` rate-limit bypass; bumped discord.js + MCP SDK; added a test suite.
- **2.0.0** — Rewrite from AppleScript to the Discord Bot API (discord.js).
